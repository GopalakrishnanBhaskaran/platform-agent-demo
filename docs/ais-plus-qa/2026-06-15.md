**Host:** Nate Herk · **Length:** 65 min · **Source:** Fireflies

The week before, Fable 5 had been withdrawn soon after launch. Several questions are about not depending on any one model.

## Q&A

### 1. Joe: Have you worked out how to store a shared data vault and give teams access to it?
- **Joe's situation:** after the Fable 5 withdrawal ("we got rugged"), he's rethinking a local-LLM idea and wants "files before AI". The client team is on Slack and Google Drive.
- **Nate's team setup:**
  - **Files in a Google shared drive.** One folder is read-only to everyone.
  - **Edit rights by owner:** individual process owners can edit their own files.
  - **Agents read everything there,** and everyone knows it, so nothing sensitive or private goes in.
  - **No sync step:** the data lives in the cloud, so every agent reads it in real time.
- **Access:** everyone uses the Google Workspace (GWS) CLI to read that folder.
- **The tech is interchangeable** (Notion, Dropbox, Drive). The hard part is people:
  - knowing what lives there
  - using it instead of pinging each other
  - owners keeping their docs current
- **Becoming AI-first is easier one unit at a time.** Rebuild one team's processes (say, marketing) AI-first, then pull others in. Don't migrate the whole company at once.
- **In progress: a change log** posted to a ClickUp channel. It shows who added, edited or deleted which file, and agents can read it too.
- **Getting content in:** people add files by hand or through their CLI. There's no mandated prompt; models already format Google Docs and Notion pages well.

### 2. Frank: If you rebuilt your AIOS tomorrow, would you make it multi-model (for example OpenRouter Fusion) so you're less dependent on one provider?
- **Nate wouldn't change anything.** The harness and wrapper matter much more than the model.
- **His AIOS is just files, folders and a few scripts,** so any agent can use it. Hermes, OpenClaw, Codex, Claude Code and Airtable's HyperAgent all navigate the same GitHub repo.
- **What makes it portable:** good context files, skills and sub-agents, and above all good routing.
- **The one gap is built-in memory.** Claude's auto-memory ("auto dreaming") is Claude-native, so switching to Codex loses it.
- **Fix:** route every agent to one shared `memory.md` from `CLAUDE.md` and `AGENTS.md`. Save decisions and changes there, or run an end-of-session sync skill. Have Claude summarise its existing local memory into that file.
- Frank's principle: "I don't want to pay rent and be subject to eviction. I want to build a foundation."

### 3. Mike: How do you publish YouTube videos so fast?
- **An agent council for confidence:** Nate uses Claude Code agent teams. About 10 agents with different backgrounds, personalities and motivations debate his outline and come back with a consensus of what's strong, what's missing, and whether he's ready to record.
- **Reps:**
  - He records in one take (a 12-minute raw recording becomes about 11 minutes edited).
  - He edits in roughly the video's own length.
  - He makes the thumbnail while it uploads.
- Heavily edited videos go to his human editing team or HyperFrames. Tutorials and news videos he edits himself, mainly cutting stutters.

### 6. Sergei: Should I onboard clients to their AIOS in VS Code or the Claude desktop app? The VS Code folder view seems scary for non-technical people.
- **Your job is to manage their overwhelm.** If they feel overwhelmed, they may tie that feeling to you, or decide AI isn't for them.
- **Ask up front what they're nervous about** and tailor to that. If the terminal scares them, never show it.
- **The Claude Code desktop app is a great start.** It feels like Claude on the web, with projects and files on the side, and covers about 95% of what matters. You only lose a few slash commands.
- Tell them the fundamentals transfer (files and folders, clearing context), so they aren't painting themselves into a corner. Skip VS Code folder structure; that's where you lose them.

### 7. Garry: What tools make a realistic product demo of my AI back-office platform and consultancy? I've tried Veo 3.1, ElevenLabs and Claude Code storyboards.
- **Why not make it fully real?** A 60-second founder-on-camera demo builds trust, and consultancy clients want a face, not an avatar.

### 8. Payman: Is Trigger.dev with Claude Code really better and easier than n8n? I'm in the EU and data can't leave it.
- **Read Zeon's pinned AIS+ post** comparing Claude Code, Trigger.dev and n8n.
- **Both can do about 80% of the same work.** The difference is preference: visual debugging, where you host, and who pays for hosting. Nate hasn't opened n8n in months.
- **For GDPR, lock down two things:**
  1. **Where the data lives.** Both n8n (self-hosted) and Claude Code-written scripts can run on a local machine or an EU VPS.
  2. **Which AI model it touches.** For full control you likely need an open-source model rather than sending data to Anthropic.
- **Can Trigger.dev be self-hosted?** Nate only uses its cloud and isn't sure. You can use another runtime, Modal, or a VPS running cron jobs and webhooks.
- **Nate's own stack:**
  - Claude Code or Codex writes TypeScript.
  - It's pushed to GitHub and deployed to Trigger.dev (with secrets) for crons and webhooks.
  - Plus a few Claude Code routines and Hermes agents.

### 9. John T.: My agent has a skills library and file-based memory, yet it still says "I can't" or rebuilds things that exist. How do I make it check first?
- **Note:** non-Claude models inside Claude Code don't know the harness as well ("the wrong gas in your car"). John's main agent is Opus, with Gemini and ChatGPT consulted as a "council", so routing is the real issue.
- **Treat `CLAUDE.md` as a router,** not as the context itself:
  - "All skills live here, all context here, all business decisions here."
  - Point to the most-used items.
  - Add decision logic: "before answering, check these four places for something that already exists."
- **Turn every miss into a rule.** "I gave you X; you should have searched this file and used that. Update `CLAUDE.md` so this doesn't happen again." That's why Nate's AIOS gets smarter with every conversation.

### 10. John F.: When do you use a CLI vs an API vs an MCP server? What's Printing Press for?
- **Nate's decision ladder:** CLI first, API second, MCP third. He almost never uses MCP servers unless they're the only option.
- **CLIs** are built for agents: cheaper, faster and more efficient, since models are trained on so much code.
- **APIs** are robust. You choose the endpoints and scope keys (read-only, for example). Use an API in deployed automations that have no shell access.
- **Printing Press** turned his favourite APIs into CLIs. He used it heavily for a week and now just uses the CLIs.

### 11. Shufang: A lead wants an AI brain from his research, starting with a chatbot for his fans. Where do I start, and why not just use Chatbase?

- You can build your own front end that reads the repo or vector database and pay token costs instead of a subscription. Nate would recommend that.

## Key takeaways
1. **Build on files, not on a model.** An AIOS of folders, context files, skills and good routing works with any harness (Claude Code, Codex, Hermes, OpenClaw).
2. **Make memory portable.** Move tool-native memory into a shared `memory.md` that every agent is routed to.
3. **Share a team brain from one read-only cloud folder** that every agent reads in real time, with owner-only edits and a change log. Adoption is the hard part.
4. **Use `CLAUDE.md` as a router** with "check here first" rules, and turn every agent mistake into a new rule.
5. **Prefer CLI, then API, then MCP** for control, cost and efficiency.
6. **For GDPR,** control where data lives and which model touches it.
7. **Lean into domain expertise and start with consulting hours.** Manage client overwhelm by meeting them where they're comfortable.
